# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ScoreSort is a macOS SwiftUI app for managing music PDFs. It has five tools, each a tab: Combine PDFs, Sheet Music Renamer, Split PDF, Rotate Pages, Stamp. macOS 14.0+, Xcode 16+. Bundle id `benperche.ScoreSort`. Distributed via GitHub releases (Developer ID–signed, notarised DMG) with Sparkle auto-update; not on the App Store.

## Read this first

**`ScoreSort_CodeRef.md` is the authoritative map of the codebase** — a detailed, per-tab breakdown of every view, view model, data model, pure function, and known gotcha. Read it before exploring or modifying code; it is far faster than reading the source directly. Keep it updated when you change architecture.

## Code layout

The app is split by feature. **Each tab has its own file(s); shared app scaffolding remains in `ScoreSort/ScanReorienterApp_complete.swift` (~1,700 lines).**

- **Tabs:** `Combine/CombineTab.swift`; `Rename/RenameViews.swift` + `Rename/RenamerManager.swift`; `Split/SplitView.swift` (Step 1) + `Split/ScanSplitSheet.swift` ("Split Double Pages" — cutting two-page scans) + `Split/SplitBookmarks.swift` (the "this PDF has bookmarks" sheet) + `Split/SplitNaming.swift` (Step 2) + `Split/SplitPrefixStep.swift` (Step 3, shared with Bulk Rename); `Rotate/RotateTab.swift`; `Stamp/StampTab.swift` (⌘5 — designs stamps + stamps existing PDFs) + `Stamp/StampStore.swift`. `StampTab.swift` also holds `StampMenuButton`, the toolbar pull-down Combine and Split use to stamp their own output.
- **Pure logic** (`ScoreSort/Logic/`): `InstrumentNames.swift` (preset matching + split instrument suggestions/detection), `SplitLogic.swift` (split maths, A3, bookmarks, booklet *de*imposition), `ScanSplitLogic.swift` (double-page scans: gutter/scanner-bed detection, blank pieces, the crop-box split), `BookletLogic.swift` (booklet *imposition* for Combine — the inverse permutation, padding, per-part segments), `BookletCalibration.swift` (the generated two-sided test sheet + per-printer duplex memory), `RenameLogic.swift` (folder-job helpers, score-order numbering, Step 3's `PrefixItem`/`scoreOrderSorted`/`scoreOrderFileNames`, and the Rename tab's planner `planScoreOrderRename` + `performRenames`), `PresetMatching.swift` (`matchPreset` — a Combine preset's copies onto files), `PartFolders.swift` ("Sort into folders" — which section/instrument folder a part goes in; Split, both Rename panels and the CLI; its menu is `Rename/PartFolderPicker.swift`), `FileUtilities.swift` (output dir, filename validation, permissions, page-range formatting), `StampLogic.swift` (stamp model, placement, drawing, flattening), `ImagePages.swift` (images → A4 PDF pages, shared by Combine and Stamp), `PrintLogic.swift` (system print dialog for a `PDFDocument`), `OutlineLogic.swift` (`outlineReadyDocument(from:)`, so an outline survives saving), `PDFSaving.swift` (`savePDFDocument(_:to:)` and the unreadable-input messages — saving with a real reason on failure).
- **Command line + MCP server** (`ScoreSort/CLI/`): `Entry.swift` (the `@main` — a known verb runs headless, anything else starts the app), `CLI.swift` (command registry, help), `CommandSupport.swift` (`CommandResult`, the strict argument parser, page lists, JSON), `FindCommands.swift` (`find` — files by name, only in folders shared in Settings ▸ AI Assistants), `InspectCommands.swift` (`info`, `preview`), `SplitCommands.swift` (`split`, `split-scans`), `RenameCommands.swift` (`rename`), `CombineCommands.swift` (`combine`, `presets`, `stamp`, `stamps`), `AllocationCommands.swift` (`allocate`, and the preset allocation `combine` shares), `MCPServer.swift` (`ScoreSort mcp`, and the `help ai` guide text), `AIAssistantsPreferences.swift` (Settings ▸ AI Assistants: Connect to Claude, Install Command, Copy Setup; settings-file/script logic in `Logic/AIConnection.swift`). So an AI assistant can use ScoreSort; see "AI access" below.
- **The main file (`ScanReorienterApp_complete.swift`)** now holds only the shared scaffolding: `@main` app + `ContentView`, `AppState`, the menu-command structs + `CombineMenuState`, Sparkle updater, About/AppDelegate, the welcome tour, **all three Preferences panes**, and shared infra (`DropZoneView`, `PDFPageView`, `PDFManager`, Sendable utils). The filename is legacy and doesn't match the app name (renamed from "Music PDF Manager" / "Music PDF Wrangler").

It's all **one module/target**, so functions/views call across files with no imports and access control is unchanged (helpers used across files are `internal`, not `private`). **When searching, grep the whole `ScoreSort/` tree.** The Xcode project uses **filesystem-synchronized groups**, so any `.swift` file added under `ScoreSort/` compiles automatically — no `.pbxproj` edits to add files. When extracting further, cut along `// MARK:` boundaries and build + run the full suite (incl. `ViewSmokeTests`, which host each tab and catch a view that fails to construct) after each move.

## Build, run, test

```bash
# Build (Release is the default config if -scheme/-configuration omitted)
xcodebuild -project ScoreSort.xcodeproj -scheme ScoreSort -configuration Debug build

# Run all tests
xcodebuild -project ScoreSort.xcodeproj -scheme ScoreSort test

# Run a single test suite or test (Swift Testing -> use the filter)
xcodebuild -project ScoreSort.xcodeproj -scheme ScoreSort test \
  -only-testing:ScoreSortTests/CombineManagerTests
```

Day-to-day, the app is normally built and run from Xcode with ⌘R.

## Tests

- Target `ScoreSortTests`, single file `ScoreSortTests/Music_PDF_ManagerTests.swift` (note the legacy name), `@testable import ScoreSort`.
- Uses the **Swift Testing** framework (`@Suite` / `@Test` / `#expect`), not XCTest.
- Tests target the **pure functions and view-model logic** (split-size math, instrument detection, roman-numeral normalisation, booklet deimposition permutations, A3 detection/splitting, combine page-count output). UI/integration is not tested.
- `writePDF(pages:to:)` is the shared helper that produces real PDFs via PDFKit for tests.
- **CI runs the whole suite on every push to `main` and every pull request** (`.github/workflows/tests.yml`: GitHub's `xcode-27` runner, Xcode 27.2, through the shared `ScoreSort` scheme). After pushing, check it: `gh run list --workflow tests.yml --limit 1`. Pushes that only touch `docs/` or `.md` files don't run it.
- **Tests never use the real saved files.** Build `EnsemblePresetStore` / `StampStore` with a temporary `fileURL` (or `nil` for in-memory), never the default; both read and write through `Logic/SavedListFile.swift`, which sets an unreadable file aside rather than saving over it.
- **`CodeRef/` is the code reference being split out of `ScoreSort_CodeRef.md`** (issue #13, in progress): `shared.md`, `combine.md` and `rename.md` are done and verified; for every other area the old file is still the reference.

## Architecture notes that span files/concepts

- **MVVM with `ObservableObject` view models**, injected as `@EnvironmentObject` at app level: `AppState`, `RenamerManager`, `EnsemblePresetStore`, `StampStore`. `PDFManager` is shared by the Split and Rotate tabs as *separate* `@StateObject` instances. `CombineManager` backs the Combine tab.
- **Three independent persistence files** in `~/Library/Application Support/ScoreSort/`: `ensemble-presets.json` (Combine tab presets — names + per-part copy counts), `instrument-orders.json` (Renamer tab instrument order — name strings only, versioned, regenerated on launch if stale), and `stamps.json` (saved stamp designs, `StampStore`). These systems do not interact.
- **Stamp text is rich text** — `Stamp.richTextData` (RTF) is the source of truth when present, so bold/italic/font/size/colour vary run by run; `fontFamily`/`isBold`/… are only the *base* attributes for unformatted text. Editing goes through `StampTextEditor` (an `NSTextView`; SwiftUI's `TextEditor` can't carry attributes on macOS 14) and `AppState.stampFormatter`.
- **Stamping flattens into page content** (`Logic/StampLogic.swift`) — it rebuilds pages through a `CGPDFContext`, so it **drops document outlines and source annotations**. Anything that stamps must do so *before* building a `PDFOutline` (page indices survive). It reads the **crop box**, not the media box, or A3-split halves come back.
- **Attach outlines to `outlineReadyDocument(from:)`, not to a document PDFKit opened.** On macOS 27, PDFKit saves a `PDFDocument(data:)`/`PDFDocument(url:)` document with the outline it was opened with unless pages were inserted or removed, so a newly set (or edited) `outlineRoot` never reaches the file. Only the outline: rotation, boxes, annotations and document attributes save normally. Stamping and imposition return exactly such documents; this silently stripped the table of contents from stamped and booklet Combine output. Test outlines by writing the file and reopening it (`CombineBookmarkSavingTests`), with Core Graphics–drawn fixtures: `PDFPage()`-built documents don't show the bug.
- **The menu bar is standard File / Edit / View + one adaptive "Actions" menu.** Each tab publishes a `TabSlice` (contextual Open/Save/Preview/Clear closures + a `[MenuAction]` list) into the app-level `TabCommands` bridge (`AppState.tabCommands`) via its own `syncTabCommands()`, called on `.onAppear` and relevant `.onChange`. **Only the active tab writes** — every `syncTabCommands()` guards on `appState.selectedTab == myTab`, so the slice always reflects the on-screen tab. The command structs (`FileCommands`/`ViewCommands`/`TabActionsCommands` in the main file) read the slice. `CombineMenuState` still exists for Combine's bare-key `onKeyPress` selection nav (arrows/c) + `isPanelOpen`.
- **Menus bind only non-editing modifier shortcuts** (⌘S/⌘O/⇧⌘P/⌘⌫/⌥⌘P/⌘1–5, plus Format's ⌘B/⌘I — safe because nothing else uses them and `StampTextFormatter` is inert unless a stamp text view is focused). Standard-editing keys (⌘A/⌘Z/⌫) and all bare keys (Space, S, R, `,` `.`, arrows) stay in each tab's `onKeyPress`/`NSEvent` handlers with their text-field guards, and are documented in `ShortcutsHelpView` (the ⌘` overlay) — the complete shortcut reference. The "Actions" menu title is fixed (SwiftUI can't reliably retitle a `CommandMenu`); its contents swap per tab.
- **PDF export methods never show UI** — they take a `PDFAlertHandler` callback (`(title, message, isError) -> Void`). Surface errors through that, not directly. **Say why**: `PDFDocument.write(to:)` returns only a Bool, so save through `savePDFDocument(_:to:)` (real error text), and Combine's `buildDocument` reports inputs it couldn't reopen (`unreadable`) rather than skipping them — files are reopened at build time, not when added, so one moved or unreadable since then used to vanish from the output, and if all did, the empty document failed with a bare "Failed to create PDF". **Combine and the Stamp tab follow moved files** via a bookmark on each `CombineFile` / `StampFileItem` (shared `FollowsMovedFile` protocol; refreshed before every output, and by Stamp's preview); a bookmark follows a file into the Trash, so `currentLocation(ofBookmark:)` treats a Trash path as gone.
- **Combine's three outputs all funnel through `buildDocument(options:stampJob:)`** so Create PDF / Print / Open in Preview can't drift. `CombineOutputOptions` carries the layout (single pages vs booklet), sheet size and duplex preference. Inside, the order is **stamp → impose → outline**: stamps must land on reading pages, and both stamping and imposition rebuild page content (dropping outlines), so the TOC is built last. Booklet segments come from the bookmark indices, which already exist one-per-part-per-copy.
- **Instrument detection is leftmost-match** (not longest-match), with a length-descending sort as tie-breaker so "bass clarinet" beats "clarinet". The static order arrays' ordering also matters as a secondary tie-break.

## AI access: command line + MCP (`ScoreSort/CLI/`)

- **The app executable is also a CLI** (`/Applications/ScoreSort.app/Contents/MacOS/ScoreSort <verb>`) and an MCP server (`… mcp`, JSON-RPC over stdio). `ScoreSortEntry` (`CLI/Entry.swift`) is the `@main`: only an explicit verb switches modes (Xcode/Launch Services pass `-NS…` args), never when `XCTestConfigurationFilePath` is set, and it branches *before* `ScoreSortApp.main()` so commands skip Sparkle, the tour and the window.
- **One implementation, three callers.** Commands call the same logic as the tabs — `writeSplitFiles`/`splitFilePlans` (Split), `scoreOrderSorted`/`scoreOrderFileNames` (Step 3), `planScoreOrderRename`/`performRenames` (Rename), `matchPreset` + `CombineManager.createCombinedPDF` (Combine), `analyseScanSources`/`splitScans` (Split Double Pages). **Change behaviour there, not in a command**, or the app and CLI drift. MCP tools convert JSON arguments into the CLI's own argv and run the same `CommandSpec` (`ScoreSortMCPServer.argv`); `MCPServerTests` checks every tool option exists on its command.
- **Rules every command keeps:** `--json`; nothing overwritten without `--overwrite`; `--dry-run` writes (and creates) nothing; `rename` plans until `--apply`; `stamp` never replaces originals; unknown options are errors; errors say why. Read saved presets/stamps from the JSON files directly (`savedPresets`, `savedStamps`) — `StampStore()` seeds a placeholder stamp.
- **MCP stdout is protocol only:** `run()` writes to a `dup` of fd 1 and points fd 1 at stderr, so a stray `print` can't corrupt the stream. Never `print` to the protocol handle.
- **`find` searches only folders the user shared** (Settings ▸ AI Assistants, `AIConnection.sharedFolders`, UserDefaults `aiSharedFolders`, read by the CLI/MCP too — same bundle) or a folder given by path. Don't make it trawl Downloads/Desktop/Documents: that exposed CVs and bank statements in testing, and relies on folder permissions Apple keeps tightening. Anything else comes in by path (Finder ⌥⌘C). A file dragged into a chat is a copy in the conversation, never on the Mac.
- **ScoreSort can't read page text**; the AI reads part names from `preview --top --sheet` (a labelled contact sheet). Keep that path fast and small.
- **Connecting to Claude rewrites `~/Library/Application Support/Claude/claude_desktop_config.json` only while Claude is quit** — Claude keeps the file in memory and writes it back, overwriting any change made while it runs (observed within a minute). The pane quits Claude, waits, writes (adding/removing only `mcpServers.scoresort`, refusing a file that isn't a JSON object, keeping it 0600), then reopens it. Never test Connect from a Claude Code session running inside the Claude app: quitting Claude ends the session. The entry points at `Bundle.main.executablePath`, so a translocated app (run from Downloads) is refused, and a moved app shows "connected elsewhere".
- **Run the debug binary from outside the repo** — it's coverage-instrumented and drops `default.profraw` in its working directory. Tests must never *set* `RenamerManager.prefixSeparator` (it writes the user's real defaults).

## Known gotchas (see CodeRef "Known Patterns & Gotchas" for the full list)

- **`fileSizes: [Int]` is the source of truth for splits**; `splitMarkers` is a *derived* computed property for rendering only.
- **`suppressDocumentReset` / `suppressNextA3Detection`** are flags set immediately before replacing `pdfManager.pdfDocument` in-place (page swap, booklet reorder, A3) so `onChange` doesn't wipe split state or re-trigger detection.
- **`page.rotation` is clockwise degrees** (PDF spec). A3 splitting and `isA3Landscape` must swap width/height when `rotation % 180 != 0`, and split along the Y axis for 90°/270° pages. The Rotate tab uses rotation *metadata*, not geometric transforms.
- **`.sheet(item:)` not `.sheet(isPresented:)`** to avoid a blank-sheet bug.
- **Don't duplicate `FocusState` across parent/child** — pass the `Binding`; a local copy steals the first TextField click.
- **`editMode` is iOS-only**; on macOS `ForEach.onMove` inside a `List` gives drag-to-reorder for free.
- **Printing goes through PDFKit, never a hand-rolled view.** `PDFDocument.printOperation(for:scalingMode:autoRotate:)` works and backs the Combine tab's Print (⌘P, `Logic/PrintLogic.swift`). `NSPrintOperation(view:)` with a custom page-drawing `NSView` — the original attempt — and AppleScript automation both fail reliably. **Duplex can't be set from code** — the print panel overwrites `com_apple_print_PrintSettings_PMDuplexing` from the printer's own preset as soon as it appears (measured exhaustively; `PMSetDuplex` isn't in the public SDK either). The app therefore compensates in the *layout*: `BookletDuplexFlip.longEdge` rotates every back face 180°, because a long-edge duplexer turns a landscape sheet upside down between sides. Confirmed on paper. **This applies on the print path only** (`printCombined` / `testSheetDocument`). Create PDF and Preview deliberately stay upright: exporting a booklet to print later — at another site, or by someone else — is a normal workflow, and the printer is unknown at export time. A saved file must therefore be an ordinary readable booklet with the page order solved, leaving whoever prints it to apply their own printer knowledge. Don't extend the compensation to the saved outputs. "Set Up Two-Sided Printing…" in the output menu (`Logic/BookletCalibration.swift` + `BookletDuplexSetupView`) prints one *generated* numbered sheet through the real imposition and sets the flip from the user's answer. The flip is stored **per printer** (`BookletDuplexDefaults`), not in `@AppStorage`, because it's a property of the machine. When probing the print dialog, **always set `info.jobDisposition = .save` first** — dismissing a print sheet programmatically reads as OK and spools a real job. **Set `NSPrintInfo.orientation` from the document's own page size** — booklet sheets are landscape and otherwise land on portrait paper — and keep centring **on** (the fold must sit at the paper's centre; centring only translates) with `scalingMode: .pageScaleDownToFit` (1:1 clips at the printer's unprintable margin). `.pageScaleDownToFit` **ignores `NSPrintInfo.scalingFactor`**, so the print dialog's Scale box is inert by design; scaling is `CombineOutputOptions.bookletPageScale`, applied during imposition so it reaches Create PDF and Preview too.
- **Booklet printing is not a macOS feature** — it's a printer-driver PPD option where it exists at all, and AirPrint queues never expose it. The app imposes booklets itself (`Logic/BookletLogic.swift`) and prints an ordinary two-up PDF; don't reach for a driver Booklet option, which would double-impose.

## Design decisions & rationale (from the build history)

These are non-obvious *whys* established across the sessions that built the app — respect them rather than re-litigating:

- **PDF export methods take a `PDFAlertHandler` callback instead of showing alerts** — done both for testability (it unblocked unit-testing `createCombinedPDF`) and because Ben deliberately wanted fewer alert dialogs in the UX. Don't reintroduce `NSAlert` inside manager/model methods.
- **⌘A / standard-editing keys are handled in `onKeyPress`, never as a `CommandMenu` `.keyboardShortcut`** — SwiftUI `CommandMenu` shortcuts intercept globally *even when the menu item is `.disabled()`*, which broke ⌘A inside the save panel's text field. This is why the menu bar deliberately binds only *non-editing* modifier shortcuts (see the architecture note above). Combine-tab shortcuts are additionally gated on `CombineMenuState.isPanelOpen`.
- **File open/save panels use `beginSheetModal(for:)`, not `begin { }`** — the sheet-modal form greys out and locks the main window (matching Word-style behaviour Ben asked for) and stops keystrokes leaking to the main window behind the panel.
- **The A3 page-reorder UI lives inside Step 1, not a separate stage.** A dedicated `A3PageOrderView` was built and then removed — it was slow and had `FocusState`/keyboard problems. The replacement is "Swap with Next" (`S`) in Step 1 plus the "Fix Booklet Order" sheet. Don't resurrect a separate reorder stage.
- **Delete/backspace uses `NSEvent.addLocalMonitorForEvents(matching: .keyDown)`** — SwiftUI's `onKeyPress` does not reliably catch the delete key on macOS.
- **Preset/name matching prefers graceful fallback over partial fill** — if bookmark labels don't cleanly parse as `"NN - Piece - Part"`, fall back to default behaviour rather than half-filling. Unmatched files/parts are highlighted orange and left for manual matching on purpose: real ensembles (Sydney school bands) have irregular parts — e.g. bass-guitar players covering whatever part exists — that Ben is always happy to assign by hand.
- **Version comes from `Bundle.main` `CFBundleShortVersionString`**, not a hardcoded constant, and tracks the GitHub release version.
- **Distribution is direct, not the App Store**: a Developer ID–signed, notarised and stapled DMG on GitHub Releases, updated with Sparkle (steps in the README's "Releasing Updates"). There are no App Store plans, so the AI access (CLI + MCP, which needs to read files wherever the user keeps them) doesn't have to survive sandboxing.

## Workflow conventions (from project memory)

- Work happens in a git worktree; merge and push directly to `main` — no extra feature branches needed.
- When switching worktrees, remember to switch the branch in Xcode too.
- **Commit after every substantial change** — i.e. at the end of each prompt that produces a working, building change, without waiting to be asked. Group the change into one descriptive commit; don't batch multiple prompts' worth of work into a single commit. Trivial/no-op changes don't need their own commit.
- **Add a line to `RELEASE_NOTES_NEXT.md` in the same commit**, for anything a user would notice — a new feature, a changed workflow, a fixed bug, a moved control. Write it for a musician, not a developer: what changed for them and why it matters, not how it was implemented. Skip it only for genuinely invisible work (refactors, tests, docs, tooling). Don't wait until release time to reconstruct the list — that's how changes get shipped unmentioned, which happened after 1.8.0 (three user-facing changes were missing from the draft and had to be dug out of the log).
- **Batch your pushes, don't push after every commit.** Every push to `main` triggers a **legacy GitHub Pages build** (source = `main` `/docs`), which serves the Sparkle **appcast** at `benperche.github.io/ScoreSort/appcast.xml`. A rapid burst of pushes races those builds and can **wedge one in `building`**, which holds the `github-pages` environment lock and makes every later deploy fail with *"Deployment failed, try again later."* So: commit freely, but `git push` **once at the end** of a working session (or a small handful of times), not after each commit. GitHub's status page will still say "operational" — it's a per-repo stuck build, not an outage.
- **If Pages is stuck** (deploys failing / `gh api repos/benperche/ScoreSort/pages --jq .status` shows `building` and not clearing): request a fresh build to supersede the wedged one — `gh api -X POST repos/benperche/ScoreSort/pages/builds` — then confirm `…/pages/builds/latest` reaches `built` and the live appcast shows the new version. (Manual equivalent: Settings ▸ Pages / Environments ▸ github-pages.) The DMG + GitHub Release are unaffected by this — only the appcast feed is delayed.
