# Command line, MCP server, Settings ▸ AI Assistants

Files: `ScoreSort/CLI/Entry.swift` (`@main`), `CLI/CLI.swift` (command registry, help), `CLI/CommandSupport.swift` (results, the argument parser, page lists, JSON), `CLI/FindCommands.swift` (`find`), `CLI/InspectCommands.swift` (`info`, `preview`), `CLI/SplitCommands.swift` (`split`, `split-scans`, `stampJob(named:scope:stampsFile:)`), `CLI/SavedListReading.swift` (`CLISavedList`, `savedPresets(at:)`, `savedStamps(at:)`), `CLI/RenameCommands.swift` (`rename`), `CLI/AllocationCommands.swift` (`allocate` and the allocation `combine` shares), `CLI/CombineCommands.swift` (`combine`, `presets`, `stamp`, `stamps`), `CLI/MCPServer.swift` (`ScoreSort mcp`, `aiGuideText`), `CLI/AIAssistantsPreferences.swift` (the Settings pane), `Logic/AIConnection.swift` (the pane's pure settings-file and script logic).

So an AI assistant can use ScoreSort: through a terminal (the CLI) or a chat app (MCP).

Gotchas that concern this area: [gotchas.md § Command line and MCP](gotchas.md#command-line-and-mcp), [§ Saved files](gotchas.md#saved-files).

## Entry and rules

**The app executable is the CLI** (`/Applications/ScoreSort.app/Contents/MacOS/ScoreSort <verb>`). `ScoreSortEntry.main()` checks `ScoreSortCLI.isCommandLineInvocation(args)` — true only for an explicit verb (a command name, `help`/`--help`, `version`/`--version`, `mcp`), because Xcode and Launch Services pass their own `-NS…` arguments — and never when `XCTestConfigurationFilePath` is set (tests host inside the app). A command runs `ScoreSortCLI.main(args)` and `exit`s **before** `ScoreSortApp.main()`, so it never touches Sparkle's launch count, the welcome tour, the window, or the instrument-orders rewrite at launch (`rename` calls `InstrumentOrders.setup()` itself). Commands run synchronously on the main actor; the heavy rendering and analysis is `nonisolated` and parallel (`renderScans`, `analyseScanSources`).

**One implementation, three callers.** Commands call the same logic as the tabs — `writeSplitFiles`/`splitFilePlans`, `scoreOrderSorted`/`scoreOrderFileNames`, `planScoreOrderRename`/`performRenames`, `matchPreset` + `CombineManager.createCombinedPDF`, `analyseScanSources`/`splitScans`, `applyingStamp`/`savePDFDocument`. **Change behaviour there, not in a command**, or the app and the CLI drift.

**Rules every command keeps:** `--json` on every command (`CLI.swift` adds it to every flag set); nothing overwritten without `--overwrite`; writing commands take `--dry-run`, which writes and creates nothing (`outputFolder(_:create: false)`); `rename` only plans until `--apply`; no command replaces its own source, even with `--overwrite` (`stamp`, `split`, `split-scans`; `combine` leaves its own output out of its inputs), decided by `isSameFile` (`Logic/FileUtilities.swift`), never by comparing paths; unknown options are errors; errors say why (`CommandError`), as `{"ok": false, "error": …}` under `--json`. Exit codes: 0 ok, 1 command failed, 2 unknown command.

**Saved presets and stamps are read straight from their files** — `savedPresets(at:)` and `savedStamps(at:)` (`CLI/SavedListReading.swift`) call `readSavedList` (`Logic/SavedListFile.swift`) and return a `CLISavedList`: read-only, entry by entry, so one entry this version can't decode doesn't hide the rest, and the CLI never sets a file aside or rewrites it. Not `StampStore()`, which seeds a placeholder stamp. **They say why** (#26): a file that can't be read at all is an error with the reason and the path (`unreadable`) — `presets` / `stamps` fail with it, and `preset(named:)` / `stampJob(named:)` throw it — never "no presets" or "not found"; entries that couldn't be read are a `warnings` note on `presets` / `stamps`, are added to a "not found" error (the one asked for may be among them), and `combine` notes a preset's stamp it couldn't use. The URL is a parameter defaulting to the store's `defaultFileURL` — `runPresets(presetsFile:stampsFile:)`, `runStamps(stampsFile:)`, `preset(named:presetsFile:)`, `stampJob(named:scope:stampsFile:)` — so tests read a damaged file from a temporary folder (`CLISavedListTests`). See [gotchas.md § Saved files](gotchas.md#saved-files).

**Run a debug binary from outside the repo**: it's coverage-instrumented and drops `default.profraw` in its working directory.

## Commands

`CommandSpec` (name, summary, help, `valueOptions`, `flagOptions`, `run: (CommandArguments) throws -> CommandResult`), registered in `ScoreSortCLI.commands` in the order `help` lists them:

| Verb | File | What it does, and through what |
|------|------|--------------------------------|
| `find` | `FindCommands.swift` | Files or folders by name, **only in the folders shared in Settings ▸ AI Assistants** (`AIConnection.sharedFolders`; missing ones skipped) or `--in` folders given by path. With none, it searches nothing and returns `pathAdvice` (Finder ⌥⌘C, or share a folder). Up to 5 levels deep, skipping hidden files, packages and developer folders (`node_modules`, `DerivedData`, `Library`…), 4 s limit. Every query word must match (start of a word, or anywhere for 4+ letters; case, diacritics and punctuation ignored). Newest first, by modification date **unless it's in the future** (then creation date). `--kind pdf` (default) / `image` / `folder` / `any`; `--limit` (20). PDFs show page counts — **except cloud-only files (`SF_DATALESS`), which are never opened**, because reading one downloads it. Folders show how many PDFs and images they hold (the help says so too). |
| `info` | `InspectCommands.swift` | Page count, sizes and rotation; `bookmarkSections` + `bookmarkSplitNames`; `isA3Landscape`/`looksLikeDoublePageScan`/`isUniformSheetScan` — the double-page verdict is suppressed when there are bookmarks (scans have none; a landscape PDF with bookmarks is probably a Combine booklet). Ends with next-step hints. |
| `preview` | `InspectCommands.swift` | Page images through `renderScans` (Core Graphics, parallel) into `--out`. `--top` = the top third, never taller than half the width; `--sheet` = `contactSheet` (labelled tiles: 24 tops or 12 pages per sheet); `--pages`; `--width` (900; in sheets 600 with `--top`, else 400); `--format jpg` (default) / `png`. **Refuses to replace existing images without `--overwrite`**, checking every name it would write before rendering anything. |
| `split` | `SplitCommands.swift` | Parts from `--part "PAGES=NAME"` (any 1-based page list, repeatable) or `--bookmarks` (`--bookmark-names title` for `.titleOnly`); `--base`, `--separator` (default the app's setting), `--skip`; names via `splitOutputFileName`; `--score-order band\|jazz\|orchestra` via `scoreOrderSorted` + `scoreOrderFileNames` (`--prefix-separator`); `--stamp`/`--stamp-scope`; `--folders section\|instrument` (+ `--ensemble`, default `--score-order`'s, else band) puts each file in its folder by part name; written with `writeSplitFiles`. Warns about unassigned or shared pages and unrecognised instruments; refuses duplicate names and existing files. |
| `split-scans` | `SplitCommands.swift` | `analyseScanSources` + `splitScans` with the sheet's defaults (one cut down the middle for uniform sheets); `--same-cut`, `--cut F`, `--per-scan`, `--first left\|right`, `--drop-blanks`. Reports each scan's pieces and `suggestedSkip` (for `split --skip`). |
| `rename` | `RenameCommands.swift` | One folder (`renamerJobFiles`, so a piece's own part folders come with it; `--recursive`) or files given one by one → `planScoreOrderRename` (`--ensemble` required, `--number "FILE=NN"`, `--exclude`, `--separator`, `--rescan`, `--folders`, `--folder "FILE=FOLDER"`). Turns on renumbering itself when `scoreOrderNeedsRenumbering` says so, and reports it. `--apply` → `performRenames`. `root` is passed only with `--folders`, so a plain rename never un-sorts a piece. |
| `allocate` | `AllocationCommands.swift` | Plans who plays what; writes nothing. `buildAllocation`: groups from `matchPreset(...).assignments`, then `--allocate "PART=FILE[:N]"` replaces a group's choice (picks without `:N` share the group's remaining players via `splitPresetCopies`); a file's copies = the sum of its groups' shares; files nobody plays = 1; `--copies "FILE=N"` last (0 = left out). `describeAllocation` → groups/files JSON plus `toDecide` (groups with no or too few copies) and `notes`. |
| `combine` | `CombineCommands.swift` | Files or a folder (name order) → `CombineManager.addFiles` → the same `buildAllocation` → `updateCopies` (files at 0 are removed, since `updateCopies` clamps to ≥ 1) → `createCombinedPDF`. `--booklet`, `--sheet double\|fit-a4`, `--blank-pages` (single pages only: a blank after odd-length parts, the app's "Blank page after odd-length parts"; `buildDocument` ignores it for booklets, which start each part fresh anyway), `--stamp`/`--stamp-scope` (the preset's stamp is used unless `--stamp` is given). JSON carries the `allocation`. A previous run's output is excluded from the inputs. |
| `presets` | `CombineCommands.swift` | Lists saved presets with each one's total players. |
| `stamp` | `CombineCommands.swift` | `pdfDocument(forFileAt:)` → `applyingStamp` (page 0 is each file's first page; a stamp that can't be applied is a problem for that file, which isn't written) → `savePDFDocument` into `--out`; `runStamp(…, job:)` takes a job directly for tests, which never read the real stamps file; `--scope` defaults to every page. **Refuses an `--out` that would put a copy on top of its source** — replacing originals is the app's job. |
| `stamps` | `CombineCommands.swift` | Lists saved stamp designs. |

**Support** (`CommandSupport.swift`): `CommandResult` (text, `json: [String: Any]`, exit code, `isError`, `images` for MCP), `CommandError` (user-facing message), `CommandArguments.parse` (strict: an unknown option is an error; `--opt v`, `--opt=v`, flags, repeatable values; `--` ends options), `parsePageList` / `describePages`, `outputFolder(_:create:)`, `jsonText`.

`aiGuideText` (in `MCPServer.swift`) is both `ScoreSort help ai` and the `scoresort_guide` tool: the recipes for common jobs. **ScoreSort can't read page text**, so the guide has the assistant read part names off `preview --top --sheet` contact sheets — keep that path fast and small.

## MCP server — `ScoreSort mcp`

Hand-rolled MCP over stdio (JSON-RPC 2.0, one message per line) rather than an SDK: it's small, and keeps the app free of another dependency.

- **`handle(_:)`** — the pure dispatcher: `initialize` (answers with the client's `protocolVersion` if it's in `supportedVersions` = 2025-06-18, 2025-03-26, 2024-11-05, else the newest; capabilities `tools`; `serverInfo`; `instructions`), `ping`, `tools/list`, `tools/call` (-32602 for an unknown tool), empty `resources/list` and `prompts/list`, no reply to `notifications/…`, -32601 otherwise. A line that isn't JSON gets -32700.
- **`run()`** — reads lines from stdin until it closes. **stdout is protocol only**: it writes to a `dup` of fd 1 and points fd 1 at stderr (`dup2`), so a stray `print` anywhere in the app goes to the log instead of corrupting the stream. Never `print` to the protocol handle.
- **Tools** — `ScoreSortMCPServer.tools`: one `Tool` per command (`scoresort_guide`, `_find`, `_info`, `_preview`, `_split_scans`, `_split`, `_rename`, `_allocate`, `_combine`, `_presets`, `_stamps`, `_stamp`), each with `name`, `command`, `title`, `effect`, `description`, `params` and optional `fillDefaults`. A `Param` maps a JSON key to a CLI option (nil = positional) with a `ParamKind`: string, number, boolean, strings (repeated option or several positionals), `pairs` (an array of two-field objects → repeated `--opt "KEY=VALUE"`), `allocations` (`[{part, file, copies?}]` → `--allocate "PART=FILE[:N]"`). `defaultValue` only where MCP's default should differ from the CLI's.
- **`argv(for:arguments:)`** builds the command line (options, then `--`, then positionals) and **`callTool`** runs the same `CommandSpec`, so validation, safety rules and results are identical. Results: text (summary + JSON), `structuredContent` (the JSON), up to 12 images (base64 JPEG/PNG; a note says how many more there were), `isError`.
- **`scoresort_preview`** defaults to top crops in contact sheets at 450 px, in a new temporary folder (`fillDefaults`), and takes an **`overwrite`** option for when the caller names `out`.
- **Tool annotations.** Each `Tool` has a `title` and an `effect` (`.readsOnly` / `.changesFiles`). `annotations(for:)` emits `title`, `readOnlyHint`, `destructiveHint` (= not read-only), `idempotentHint` (= read-only) and `openWorldHint` (always false — it works on this Mac's files and contacts nothing); `listing(for:)` puts `title` at the top level too (where 2025-06-18 looks first) and sends both whatever version was negotiated. **Hints are fixed per tool, so they describe the worst case over its arguments**: `preview` saves images and can replace them, `rename` moves files only with `apply`, yet both are `.changesFiles`. Read-only: guide, find, info, allocate, presets, stamps.

`MCPServerTests` checks every tool option exists on its command and every schema is valid; every tool has a title and annotations in the schema's shape; **the read-only set is exactly the tools whose commands have no `--out`, `--apply` or `--overwrite`**; argument conversion; a real call; preview images; and that the real executable writes only protocol to stdout.

## Settings ▸ AI Assistants

`CLI/AIAssistantsPreferences.swift` (`AIAssistantsPreferencesView`, `AIAssistantsModel`) over `Logic/AIConnection.swift` (pure, tested). The third Settings tab (`tag("ai")`), also reached from **Help ▸ Use ScoreSort with an AI Assistant…** (`OpenAIAssistantsSettingsButton`, which writes `preferredPrefsTab = "ai"` and calls `openSettings`). Everything points at this copy's `Bundle.main.executablePath`.

- **Claude desktop app** (`com.anthropic.claudefordesktop`). `ClaudeState`: not installed / not connected / connected / connected elsewhere (a moved app or another build). **Connect/Disconnect rewrites `~/Library/Application Support/Claude/claude_desktop_config.json` only while Claude is quit**, because Claude holds the file in memory and writes it back, overwriting any change made while it runs (observed within a minute). `setClaudeConnection(_:)` quits Claude if running (the view confirms first), waits up to 20 s plus a moment for its own write-back, writes `AIConnection.settingsAdding` / `settingsRemoving` (only `mcpServers.scoresort` changes; an absent or empty file starts fresh; **a file that isn't a JSON object throws and is left alone**), restores 0600, then reopens Claude. `serverEntry` adds `env.LLVM_PROFILE_FILE=/dev/null` for debug builds (coverage files). **Never test Connect from a Claude Code session running inside the Claude app**: quitting Claude ends the session.
- **Command line** — installs `/usr/local/bin/scoresort` as a `wrapperScript` (`exec '<executable>' "$@"`, shell-quoted; a script rather than a symlink so the app's frameworks load), 0755. Writes directly, falling back to `NSAppleScript` `do shell script … with administrator privileges`. `wrapperExecutable` parses an installed script back, so a `scoresort` ScoreSort didn't write is reported (`occupied`) and never replaced; one pointing at another copy is `installedElsewhere`.
- **Folders your assistant can look in** — `sharedFolders`, added through the folder picker (`beginSheetModal`; choosing is the consent), removed with −; a missing folder shows "Not found". Stored by `AIConnection.setSharedFolders` (deduplicated paths in UserDefaults `aiSharedFolders`) and read by `find` in the CLI and MCP too (same bundle id, same defaults). **Don't make `find` trawl Downloads/Desktop/Documents**: the first version did, and showed an assistant CVs and bank statements; it also relied on folder permissions Apple keeps tightening. Anything else comes in by path. A file dragged into a chat is a copy in the conversation, never on the Mac.
- A **translocated** app (run from Downloads, `/AppTranslocation/`) is refused with "move it to Applications first", since its path changes every launch. **Copy Setup** puts `setupSnippet` (the config JSON) on the pasteboard for other MCP clients.

There are no App Store plans, so this access — which needs to read files wherever the user keeps them — doesn't have to survive sandboxing.
